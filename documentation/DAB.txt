GUIA DE REFERÊNCIA RÁPIDA: DATA API BUILDER (DAB)

1. OPERAÇÕES E VERBOS HTTP (CRUD)
--------------------------------------------------------------------------------
- GET    -> SELECT (Listar): /api/Entidade
- GET    -> SELECT (Por ID): /api/Entidade/PK_Nome/Valor
- POST   -> INSERT: /api/Entidade (Requer JSON no Body com os novos dados)
- PUT    -> UPDATE (Total): /api/Entidade/PK_Nome/Valor (Substitui todo o objeto)
- PATCH  -> UPDATE (Parcial): /api/Entidade/PK_Nome/Valor (Muda apenas campos no Body)
- DELETE -> DELETE: /api/Entidade/PK_Nome/Valor (Remove o registo físico)

2. PARÂMETROS DE CONSULTA ODATA (USADOS NO URL COM GET)
--------------------------------------------------------------------------------
- $filter  : Filtra resultados (WHERE). 
             Ex: /api/Peca?$filter=StockAtual lt 10 and Ativo eq true
             Operadores: eq (=), ne (!=), gt (>), lt (<), ge (>=), le (<=), and, or, not.
- $expand  : Realiza JOINs com relações definidas. 
             Ex: /api/Cliente?$expand=trotinetes
- $select  : Escolhe colunas específicas (SELECT col1, col2). 
             Ex: /api/Funcionario?$select=Nome,Cargo
- $orderby : Ordena os dados (ORDER BY). 
             Ex: /api/Servico?$orderby=DataAgendamento desc
- $first   : Limita o número de resultados (TOP). 
             Ex: /api/Venda?$first=10

3. ESTRUTURA DO FICHEIRO dab-config.json
--------------------------------------------------------------------------------
O ficheiro é dividido em três pilares fundamentais:

A. RUNTIME: Define o comportamento global do motor.
   - rest & graphql: Ativa protocolos e define prefixos de URL (ex: /api).
   - host: Define o modo (development/production) e regras de CORS para o Frontend.

B. DATA-SOURCE: Configuração da ligação à Base de Dados.
   - database-type: Define o motor (mssql, postgresql, mysql, etc.).
   - connection-string: Ligação ao SQL (usar @env('VAR') para segurança).

C. ENTITIES: Mapeamento de tabelas para a API.
   - source: Nome real da tabela ou view no SQL (ex: dbo.Clientes).
   - permissions: Define o RBAC (Controlo de Acesso). Permite restringir ações 
     (create, read, update, delete) por Role e aplicar políticas de base de dados
     (ex: @item.ID eq @claims.user_id).
   - relationships: Define como as tabelas se ligam. Especifica cardinalidade 
     (one ou many) e os campos de ligação (Foreign Keys) entre source e target.

DICA DE REPOSITÓRIO:
Para acesso total via Backend .NET, incluir sempre o Header:
X-MS-API-ROLE: Administrador
